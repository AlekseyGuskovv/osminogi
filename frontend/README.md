# Cyber Garden

React-редактор сценариев проверки Kotlin-проектов. Для запуска нужны Python-бэкенд и Node.js 22.12+ или 24.

## Запуск на Windows

Из корня репозитория в первом PowerShell запустите бэкенд. Если виртуальная среда находится в другой папке, подставьте путь к её Python.

```powershell
..\.venv\Scripts\python.exe -m backend.app.demo_server
```

Во втором PowerShell из корня репозитория запустите интерфейс.

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Откройте `http://localhost:5173`. Vite передаёт API-запросы и события на `127.0.0.1:8000`. Если порт бэкенда отличается, перед запуском Vite задайте `$env:GARDEN_BACKEND_URL = "http://127.0.0.1:8007"`.

## Показать за две минуты

1. Нажмите **Режим демонстрации → Запустить учебную проверку → Запустить**. На исходном снимке появится критическая находка, граф пойдёт по ветке **Да**, CI будет заблокирован.
2. Выберите **После правок → Запустить**. CI пройдёт, граф пойдёт по ветке **Нет**. По ссылке **Открыть отчёт** доступны находки, сравнение и повтор на графе.
3. Для своего сценария нажмите **Проект организаторов** или **Загрузить ZIP**, добавьте нужные блоки и нажмите **Запустить**. Редактор сохранит изменения перед запуском.

**Проект организаторов** загружает исходники и официальный справочник зависимостей из одного коммита. Версия справочника видна в карточке запуска и Markdown-отчёте. Для загруженного вручную ZIP действует справочник сервера. Другой файл можно задать через `GARDEN_ADVISORIES`.

### Модель, Telegram и CI

По умолчанию действует `GARDEN_LLM_PROVIDER=auto`. Каждый AI-запрос сначала идёт в CodexGenerator. При ошибке клиента, тайм-ауте или нечитаемом JSON сервер один раз пробует локальную Ollama. Если обе попытки завершаются ошибкой, интерфейс показывает обе причины. Для нестандартного пути к CodexGenerator укажите `GARDEN_CODEX_DIR`.

Для переключения запустите Ollama и установите модель `qwen3:4b`. Модель и локальный порт `11434` можно переопределить через `GARDEN_OLLAMA_MODEL` и `GARDEN_OLLAMA_PORT`. Чтобы использовать только один провайдер, перед запуском бэкенда задайте `GARDEN_LLM_PROVIDER=codex` или `GARDEN_LLM_PROVIDER=ollama`.

В ноде **Telegram** выберите подключение к закрытому чату. Подтверждённая отправка показывает номер сообщения в данных ноды. YAML и Python-клиент CI скачиваются из меню **GitHub Actions** сохранённого сценария. Для этого экспорта нужен частный учебный репозиторий и настроенный self-hosted runner.

### Сценарий защиты

1. За 20 секунд объясните задачу. Команда разработчиков собирает проверку без написания кода и заранее узнаёт, что стоит исправить.
2. Нажмите **Проект организаторов**. На графе соедините **Запуск → Секреты → Зависимости → Анализ кода → Рекомендации AI → Telegram**. Покажите статусы и данные одного блока.
3. Откройте отчёт. Покажите файл, строку и критичность, а затем рекомендацию и сообщение в чате. Разработанные командой правила определяют находки, а модель получает их идентификаторы и описания. Бэкенд проверяет структуру и отклоняет неподтверждённые идентификаторы и ссылки.
4. Покажите **Повтор на графе**, шаблон и черновик из естественного текста. В GitHub откройте проверку PR и её отчёты. Объясните, что критические находки приводят к ошибке задачи CI.
